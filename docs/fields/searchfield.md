# SearchField

Стеклянная строка поиска на базе подложки `LiquidGlass` с иконкой лупы, нативным полем `<input type="search">` и умной кнопкой быстрой очистки, работающей как в контролируемом, так и в неконтролируемом режимах.

## Параметры

| Название параметра | Тип | Описание |
| --- | --- | --- |
| `width` | `number \| string` | Ширина стеклянной панели поиска (число означает пиксели). По умолчанию `280`. |
| `size` | `number` | Высота стеклянной панели поиска в пикселях. По умолчанию `36`. |
| `placeholder` | `string` | Текст-подсказка в пустом поле. По умолчанию `"Поиск…"`. Также используется как резервный `aria-label`, если `aria-label` не передан явно. |
| `onClear` | `() => void` | Колбэк, вызываемый после нажатия на кнопку очистки (после сброса значения и вызова `onChange`). |
| `clearLabel` | `string` | Доступное имя (`aria-label`) и всплывающая подсказка (`title`) для кнопки очистки. По умолчанию `"Очистить поиск"`. |
| `value` | `string \| number \| readonly string[]` | Значение поля в контролируемом режиме. |
| `defaultValue` | `string \| number \| readonly string[]` | Начальное значение поля в неконтролируемом режиме (при его динамическом изменении видимость кнопки очистки обновляется автоматически). |
| `onChange` | `ChangeEventHandler<HTMLInputElement>` | Обработчик изменения текста. Срабатывает как при обычном вводе с клавиатуры, так и при нажатии на кнопку очистки. |
| `disabled` | `boolean` | Отключает поле ввода, скрывает кнопку очистки и отключает интерактивность стеклянной подложки `LiquidGlass`. |
| `className` | `string` | Пользовательский CSS-класс. Применяется к внешней стеклянной панели `LiquidGlass`. |
| `style` | `CSSProperties` | Инлайн-стили. Применяются к внешней стеклянной панели `LiquidGlass`. |
| `ref` | `Ref<HTMLInputElement>` | Ссылка на нативный элемент `<input type="search">`. |
| `...props` | `Omit<InputHTMLAttributes<HTMLInputElement>, "size" \| "type">` | Остальные нативные атрибуты `<input>` (`name`, `autoFocus`, `onKeyDown` и др.). Атрибуты `size` и `type` зарезервированы. |

## Быстрый старт

```tsx
import { SearchField } from "./Fields";

export default function App() {
  return (
    <SearchField
      placeholder="Поиск по документам…"
      onChange={(e) => console.log("Запрос:", e.target.value)}
      onClear={() => console.log("Поиск очищен")}
    />
  );
}
```

## Примеры использования

### 1. Контролируемый режим с обработкой очистки
При клике на крестик компонент программно сбрасывает значение `<input>` и диспатчит нативное событие `input`, поэтому `onChange` автоматически получит пустую строку `""` даже без написания отдельной логики в `onClear`. При этом фокус не теряется и остаётся в поле ввода.

```tsx
const [query, setQuery] = useState("");

<SearchField
  value={query}
  onChange={(e) => setQuery(e.target.value)}
  onClear={() => console.log("Поле очищено, фокус сохранён")}
  placeholder="Найти город"
/>
```

### 2. Неконтролируемый режим и работа внутри `<form>`
Компонент сам отслеживает наличие текста в неконтролируемом режиме, чтобы показывать или скрывать кнопку очистки, а также подписывается на событие `reset` родительской формы для синхронизации состояния кнопки очистки.

```tsx
<form onReset={() => console.log("Форма сброшена")}>
  <SearchField name="search" defaultValue="Москва" />
  <button type="reset">Сбросить</button>
</form>
```

### 3. Настройка размеров и локализация
В отличие от `TextField`, строка поиска имеет собственные габариты по умолчанию (`280×36`), которые можно гибко менять через пропсы `width` и `size`.

```tsx
<SearchField
  width="100%"
  size={42}
  placeholder="Search items…"
  clearLabel="Clear search"
/>
```

## Ограничения

- **Несовпадение габаритов с `TextField` и `ComboBox`:** Высота `SearchField` по умолчанию составляет `36px` (против `32px` у `TextField`), и у него нет пропсов `label`, `hint` или `error`. Если поставить их в один ряд без выравнивания или изменения `size={32}`, они будут разной высоты.
- **Фиксированный `type="search"`:** Изменить тип поля нельзя — он жёстко задан как `"search"`.
- **Отсутствие авто-блокировки от `useFormStatus`:** В отличие от `TextField` и `Button`, `SearchField` не использует внутри себя `useFormStatus()`, поэтому при необходимости блокировать поиск во время отправки формы проп `disabled` нужно передавать вручную.
- **Стилизация через `className` и `style`:** Эти свойства передаются в обёртку `LiquidGlass`, а не на `<input>`. Передача своего `backgroundColor` в `style` перезапишет системную переменную заливки стекла `var(--search-tint)`.
